Динамические (разделяемые) библиотеки - это файлы, содержащие машинный код, который загружается в память процесса средствами ОС динамически.
Динамические библиотеки позволяют программам:
	*Использовать функции, используемые несколькими программами, — одна копия библиотеки используется несколькими процессами.
	*Обновлять библиотеки без перекомпиляции использующих их программ — достаточно заменить файл библиотеки.
	*Получать доступ к копиям общих ресурсов, разделяемым между всеми приложениями (строки, константы, изображения).Каждый процесс получает свою копию данных библиотеки (copy-on-write), истинное разделение требует механизмов разделяемой памяти (shared memory).

В зависимости от используемой ОС, динамические библиотеки могут иметь расширение .so (Shared Object) в Linux и .dll (Dynamic Link Library) в Windows.
Существует два способа связывания динамических библиотек:
	*неявная загрузка (также называется статическое связывание во время компиляции): библиотека инициализируется в момент старта процесса, всю работу по сопоставлению символов с адресами в памяти берёт на себя операционная система.
	*явная загрузка (также называется динамическое связывание): библиотека подгружается в момент выполнения за счет вызовов специальных функций: LoadLibrary() в Windows и dlopen() в Unix. В этом случае не происходит автоматического связывания символов с фактическими адресами в коде загруженной библиотеки — процесс должен сам осуществить поиск нужного символа в памяти.

В момент создания реализации библиотек на си++ стоит учитывать, что имена функций,классов  декорируются, то есть к имени функции добавляются некоторые символы. Есть два способа решения:
	*просмотр таблиц экспорта файла динамической библиотеки (инструменты dumpbin для Windows (Microsoft VS утилита) или nm для Linux)для получения точного декорированного имени, к примеру: ?CreateWaitTimer@@YAPEAXXZ В Windows или Namespace::Class::method в Linux
	*размещение необходимых функций и классов в блоке extern "C" { ... }. Данный спецификатор линковки приводит именование функций и объектов в соответствие с "СИ" и делает возможным применение недекорированных имен: CreateWaitTimer(). Стоит учитывать, что могут возникнуть сложности с перегруженными функциями и другими особенностями Си++ как ООП для данного способа.

Пример создания и использования динамической библиотеки (.so файла) в ОС Linux с использованием компилятора g++:
Для компиляции динамических библиотек при помощи компилятора g++ следует использовать команды:
1) g++ -std=c++20 -c -fPIC implementation.cpp -o impl_example.o  // получение объектного файла (.о)
2) g++ -shared -o lib_example.so impl_example.o                  // получение файла динамической библиотеки (.so) из объектного файла

Команда для получения исполняемого файла, использующего динамические библиотеки:
3) g++ -std=c++20 -o main main.cpp -L. -l_example -ldl -Wl,-rpath,.  // пример формированием исполняемого файла с использованием библиотек для неявного связывания (l_example, ldl)

В них присутствуют имена:
	* g++ - именование компилятора
	* implementation.cpp, main.cpp - имя или путь файла с .cpp реализацией вашей библиотеки и реализацией основного файла программы соответственно  (в примере файлы в данной директории).
	* impl_example.o - имя объектного файла, необходимого для дальнейшего формирования библиотеки (файла с расширением .so). В данном примере формируется в данной же директории.
	* lib_example.so - имя библиотеки (файла с расширением .so)
	
А также флаги относящиеся к компиляции:
	-std=c++20 - указание используемого стандартного стандарта языка с++ (в данном случае 20).
	-с компиляция файла без линковки(компоновки).В результате этого пропускается этап линковки файла и на выходе мы получаем не исполняемый файл, а объектный.
	-fPIC (Position Independent Code) - обязательный флаг для формирования библиотек. Задает возможность загрузки созданного кода в любой адрес памяти ( Использует относительную адресацию вместо абсолютной). -- Генерация позиционно-независимого кода (обязательно для shared libraries)
	-o - позволяет задать имя выходного файла.
	
А также флаги, относящиеся к линковке(компоновке):
	-shared - создание .so файла вместо исполняемого
	-L - Указания дополнительной директории для поиска библиотек. (В примере -L. - данная директория). (-L/usr/local/lib - указание системной директории)
	-l - Неявное связывание с библиотекой. -l опускает lib в имени(В примере -l_example и -ldl указывают библиотеки lib_example (наша библиотека) и libdl (библиотека для явного связывания).
	-Wl - передает опции(специальные флаги) непосредственно линкеру (-Wl,-rpath,. - указывает на передачу единственного флага -rpath.
	-rpath (Runtime Library Search Path) - задает путь поиска библиотек для выполнения.
